# Mitwirken

Fehler, fehlende Punkte, bessere Formulierungen — alles willkommen.

## So geht's

1. **Kleine Fixes** (Tippfehler, Klarstellungen, ergänzte Punkte):
   Pull Request direkt gegen `main`.
2. **Größere Änderungen** (neue Abschnitte, Umstrukturierung):
   Erst Issue öffnen und kurz die Richtung abstimmen.
3. **Juristische Korrekturen:** Bitte Quelle nennen (Gesetzesstelle,
   Erwägungsgrund, Rechtsprechung). "Ein Anwalt hat mir gesagt" reicht
   nicht.

## Lizenz der Beiträge

Mit dem Einreichen eines Pull Requests stimmst du zu, dass dein Beitrag
unter der [MIT-Lizenz](LICENSE) dieses Projekts steht (*inbound = outbound*).
Du behältst das Urheberrecht an deinem Beitrag, erlaubst aber die Nutzung
unter MIT.

Wenn du im Auftrag deines Arbeitgebers beiträgst, stelle sicher, dass dieser
damit einverstanden ist.

## Code of Conduct

Respektvoller Umgang ist Pflicht. Siehe [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## Worum es **nicht** geht

Das ist eine **Checkliste**, keine Rechtsberatung. Pull Requests, die
konkreten Fällen einen Persilschein ausstellen ("Wenn X, dann automatisch
konform"), werden nicht übernommen. Die Checkliste bleibt strukturierend —
die Bewertung macht der Anwalt bzw. Datenschutzbeauftragte.
